# SD-WAN Dynamic Path Selection: Python Simulation

Project: *Enhancing Data Availability and Transaction Response Time in Multi-Branch
Core Banking Information Systems through SD-WAN Dynamic Path Selection: A Case Study
of Nigerian Banks* (Professional MIT, Miva Open University).

This package is a **Python model-based simulation** of a simplified multi-branch
banking network. It compares **Static Path Selection** (primary path with
reachability-based failover) against **Dynamic Path Selection** (SLA-based steering
on latency, jitter and loss) over the 80-run experimental design of Chapter 3.

> All outputs are model-based simulation results. They are not measurements from
> any bank's production network, from physical network devices or from PNETLab.

## 1. Run it on Windows

1. Install **Python 3.10 or newer** from <https://www.python.org/downloads/>. On the
   first installer screen tick **"Add python.exe to PATH"**.
2. Unzip this folder somewhere simple, for example `C:\SDWAN_Python_Simulation`.
3. Double-click **`RUN_SIMULATION.bat`**. The first run creates a private Python
   environment and installs numpy, pandas, matplotlib, scipy and openpyxl (about a
   minute). It then runs everything (about 1 to 3 minutes) and opens
   `outputs\dashboard.html`.
4. For the defence demonstration double-click **`RUN_DEMO.bat`**.
5. To show the model checks, double-click **`RUN_TESTS.bat`**.

Command line equivalent (Windows, macOS or Linux):

```
python -m venv .venv
.venv\Scripts\activate            (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
python run_simulation.py          full run: 80 runs + 130 sensitivity runs + analysis
python run_simulation.py --quick  80 runs only
python demo.py --condition brownout --load 300
python tests/test_model.py
```

## 4. The model in one page

**Network.** HQ data centre plus 3 branches. Each branch has two WAN paths to HQ.
Path A is a private, MPLS-like path: 10 ms one-way delay, ±1 ms jitter, 2.56 Mbit/s.
Path B is broadband: 25 ms, ±3 ms, 10.24 Mbit/s. Path A is sized so 450 tps loads it
to 90 % (the Chapter 3 rate-cap rule). Faults hit Path A of all branches at 180 s of
the 420 s measurement window, for 120 s: **brownout P1** (50 ms ±20 ms, 2 % loss per
direction) or **blackout P2** (100 % loss).

**Transactions.** Poisson arrivals (50, 150, 300, 450 tps per branch). Each
transaction is a 640-byte request and a 640-byte response. Response time =
retransmission wait + request network delay + HQ processing (lognormal, median 4 ms) +
response network delay. Network delay = base delay + uniform jitter + FIFO queueing
(exact Lindley recursion) + serialisation. Lost messages are retransmitted after
0.25, 0.5, 1, 2, 4 s. No response within 10 s means a failed transaction.

**Static Path Selection.** Traffic uses Path A. A reachability probe every 1 s declares a
path down after 3 lost probes and up after 3 answered probes; traffic fails over to
Path B only when Path A is down. Latency, jitter and loss are ignored.

**Dynamic Path Selection.** Probes every 0.2 s. Latency and jitter are averaged over the
last 30 probes, loss over the last 100. A path is dead after 5 lost probes, alive after
10 answered. A path is in SLA when alive and latency ≤ 60 ms, jitter ≤ 10 ms and loss
≤ 1 %. Traffic uses the first in-SLA path in the order A, B. A probe result is known
only when its reply arrives or its 0.5 s timeout expires, so switching is never instant.

**Availability, three measures, never mixed.**

* WAN link availability = time the path can deliver traffic / measurement time × 100
* End-to-end service availability = time the branch's selected path is up / measurement time × 100
* Transaction availability (primary) = successful transactions / attempted × 100
* Supplementary: SLA-compliant service time = time the selected path meets the SLA / measurement time × 100

**Fair comparison.** Both policies in a cell use the same seed: the same arrivals,
processing times and random draws. Only the policy differs, so differences are caused
by the policy (common random numbers; tests are paired).

## 5. Reproducibility

Master seed 2026. Each run's seed is derived from (load, condition, repetition) and is
written in `run_level_results.csv`. Re-running gives identical results (verified with 1
and 4 worker processes). Software versions are in `run_manifest.json`; a different numpy
version can change the last decimals.

## 6. Defence demonstration

`RUN_DEMO.bat` runs three paired comparisons in seconds:
1. Brownout at 300 tps: static stays on the degraded path, dynamic steers to Path B in about 2 s.
2. Blackout at 300 tps: static fails over after 3 s, dynamic after under 1 s.
3. Steady state at 450 tps: dynamic selection flaps because queueing jitter on Path A sits
   at the 10 ms threshold (an honest limitation; sensitivity scenario S6 shows a hold-down fixes it).
